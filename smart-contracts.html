Smart Contracts

A smart contract is code that lives at an address on a blockchain. Anyone can send it a transaction, every node runs the same code, and the result is recorded in shared state. Because nobody controls the machine that runs it, the rules cannot be quietly changed or skipped.

How a Smart Contract Works

  1. A developer writes the contract, commonly in Solidity for Ethereum, and compiles it to bytecode.
  2. The bytecode is deployed in a transaction and receives its own address.
  3. Users or other contracts call its functions by sending transactions.
  4. Every validating node executes the function and agrees on the new state.
  5. The caller pays a gas fee that covers the computation.

Common Uses

  • Tokens, including stablecoins and NFTs
  • Decentralized exchanges and lending protocols (DeFi)
  • Escrow and automatic payouts when conditions are met
  • Voting and organization governance (DAOs)

Strengths and Limits

Tradeoffs of smart contracts
StrengthLimit
Runs automatically with no middlemanBugs are costly because deployed code is hard to change
Code and history are publicly auditableEvery action costs gas, so computation is expensive
Same behavior for every userContracts cannot read outside data without an oracle

A Tiny Example

This simplified Solidity contract stores a number that anyone can read and update.

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Counter {
    uint256 public count;

    function increment() public {
        count += 1;
    }
}
